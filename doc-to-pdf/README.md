# Convert to PDF — Finder Quick Action for macOS

Конвертация одного или нескольких файлов `.doc` / `.docx` в PDF из контекстного меню Finder. Используется установленный **Microsoft Word**; LibreOffice и сторонние Python-библиотеки не нужны.

## Возможности

- Пакетная конвертация выделенных документов через **Finder → Quick Actions → Convert to PDF**.
- PDF создаются рядом с исходниками; оригиналы не меняются.
- Имена PDF нормализуются: буквы Unicode (в том числе кириллица), цифры и `_` сохраняются; остальные символы заменяются на `_`; повторяющиеся `_` схлопываются; начальные и конечные `_` удаляются. Регистр сохраняется; расширение — `.pdf`.
- Если PDF уже существует, используется суффикс `_2`, `_3` и т. д. Перезаписи нет.
- Для Word используется **одна и та же промежуточная папка**, без новых папок на каждый документ.
- Временные файлы удаляются после каждой попытки; параллельные запуски синхронизируются блокировкой.

**Пример:** `Отчёт (финал): 2026.10.31.docx` → `Отчёт_финал_2026_10_31.pdf`.

## Требования

- macOS с Automator и Finder Quick Actions. Проверено вручную на **macOS 27 Golden Gate**.
- Установленный и активированный **Microsoft Word для Mac** (проверено на версии из Mac App Store).
- **Python 3**, доступный по пути `/usr/bin/python3`, либо изменение этого пути в Automator на реально установленный `python3`. Проверка: `/usr/bin/python3 --version`.
- Стандартные средства macOS: `/usr/bin/osascript`; никаких pip-зависимостей.
- Доступ на чтение исходных документов и запись PDF в их папки.

> В зависимости от версии macOS Python 3 может отсутствовать по пути `/usr/bin/python3` или потребовать установки Command Line Tools. Не полагайтесь на наличие Python без проверки.

## Установка с нуля

1. Установите и хотя бы один раз запустите Microsoft Word, завершив первичную настройку.
2. Скопируйте **оба** файла `doc_to_pdf.py` и `convert_word.applescript` в постоянную папку. Например:

   ```sh
   mkdir -p "$HOME/scripts/doc-to-pdf"
   # Затем скопируйте два файла из репозитория в эту папку.
   ```

   AppleScript должен лежать **рядом** с Python-скриптом: тот ищет его через `Path(__file__).with_name(...)`.

3. Откройте **Automator → New Document → Quick Action**.
4. Вверху установите: **Workflow receives current: files or folders**; **in: Finder**.
5. Добавьте действие **Run Shell Script**. Параметры: **Shell: `/bin/zsh`**; **Pass input: as arguments**.
6. Вставьте команду (путь должен точно совпадать с расположением файлов на вашем Mac):

   ```zsh
   /usr/bin/python3 "$HOME/scripts/doc-to-pdf/doc_to_pdf.py" "$@"
   ```

7. Сохраните Quick Action с названием **Convert to PDF**.
8. В Finder выделите тестовый `.docx` → **Quick Actions → Convert to PDF**. Если Word запросит разрешение на доступ к рабочей папке, выдайте его и повторите проверку.

Если Quick Action не появляется, проверьте настройки расширений Finder/Quick Actions в macOS и то, что действие сохранено как Quick Action, а не обычный workflow.

## Как работает

1. Finder передаёт выделенные пути Python-скрипту.
2. Скрипт по одному копирует документы в `~/Library/Application Support/DocToPDF/source.docx` или `source.doc`.
3. AppleScript открывает копию в Word, сохраняет `output.pdf` и закрывает документ.
4. Python копирует PDF рядом с оригиналом под нормализованным именем, не перезаписывая существующие файлы.
5. Временные `source.docx` / `source.doc` и `output.pdf` удаляются даже при ошибке.

Рабочая папка **остаётся**, как и служебный `.conversion.lock` (пустой файл для `flock`). Временные документы между запусками не хранятся. Если процесс принудительно завершён, очистка может не успеть выполниться; содержимое рабочей папки можно проверить вручную.

## Разрешения macOS и Word

Word из Mac App Store может попросить предоставить доступ к папке `~/Library/Application Support/DocToPDF`. На протестированной конфигурации после однократного разрешения повторных запросов не возникало даже после удаления временных файлов. **Это наблюдение, а не гарантия** для всех версий macOS и Word.

Разрешения **Full Disk Access** сами по себе не гарантируют отсутствие диалогов в приложении с sandbox. Не рекомендуется размещать staging-файлы непосредственно внутри `~/Library/Containers/com.microsoft.Word/`: внешнему Python-процессу может быть отказано в записи.

## Именование и ограничения

- Сохраняются буквы всех алфавитов, а не только ASCII. Для некоторых URL кириллица в ключах S3 требует percent-encoding; если нужны исключительно ASCII-имена, алгоритм надо изменить.
- Запрещённые символы `/` и `:` не могут быть частью обычного имени файла на соответствующих файловых системах, но любые подобные символы в строке имени заменяются алгоритмом.
- При большом числе конфликтов добавляются числовые суффиксы.
- Обработка последовательная, и Word может показывать окно документа; скрипт не гарантирует полностью невидимую конвертацию.
- Возможны ошибки на повреждённых файлах, файлах с паролем, недоступных каталогах, а также различия между версиями Word.
- Результаты не конвертируются в облаке: Word обрабатывает документы локально, однако поведение облачных функций самого Word зависит от его настроек.

## Диагностика

| Симптом | Что проверить |
|---|---|
| `Operation not permitted` в `~/Library/Containers/...` | Используйте текущую версию со staging в `~/Library/Application Support/DocToPDF` |
| `Variable openedDoc is not defined (-2753)` | Установите приложенный `convert_word.applescript`, где после `open` используется `active document` |
| Word просит доступ к `job_...` на каждом запуске | Установите текущий Python-скрипт: он не создаёт новых `job_...` каталогов |
| `python3` не найден | Проверьте `/usr/bin/python3 --version`; используйте доступный Python 3 и правильный путь в Automator |
| PDF не появился | Проверьте показанный текст ошибки, права записи в папку исходника, состояние Word и запросы доступа |
| Quick Action не виден в Finder | Проверьте, что в Automator выбран тип Quick Action и входные файлы из Finder |

## Безопасность

Скрипт открывает только выделенные пользователем документы, но перед публикацией в открытом репозитории проверьте файлы на личные данные и пути, специфичные для вашего Mac. На исходных файлах скрипт ничего не изменяет. Для конфиденциальных документов учитывайте, что при аварийном завершении процесса временная копия может остаться до ручной очистки.

## Проверено

Рабочий пользовательский сценарий подтверждён на macOS 27 с Word из Mac App Store: пакетная конвертация, нормализация имён, удаление временных файлов и отсутствие повторного запроса доступа после первого разрешения. На других версиях не тестировалось.
